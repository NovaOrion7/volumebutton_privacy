♿ 9. Accessibility Permission

To enable certain convenience features (for example, enhanced volume control or automatic actions tied to hardware buttons), the app may request the Android Accessibility permission. Important details:

  • Why: Accessibility access allows the app to interact with system events required to implement features that improve usability (responding to system key events, displaying persistent volume controls).
  • What we DO NOT do: We do not read or transmit your typed text, screen contents, or audio. The permission is used only to detect system-level events and to control audio settings.
  • User Control: Granting Accessibility access is optional. If you decline, the app will continue to work with reduced functionality.

🔑 11. Permissions

The App may request the following permissions. Each permission is used only for the purposes listed:

  • Modify System Audio / Audio Settings: Required to change system and stream volumes (core functionality).
  • Foreground Service: To keep volume controls available while the app is running in the background.
  • Vibration: To provide haptic feedback on certain actions.
  • Notifications: To display persistent or quick-access volume controls.
  • Internet Access: Used to download and display advertisements, process in-app purchases, and send crash reports.
  • Accessibility: Optional; explained above in the Accessibility Permission section.
  • AD_ID: To access the Android Advertising ID for serving relevant advertisements.
